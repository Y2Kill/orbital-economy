# Реестр внешних параметров (Lab v0.8.0)

## Зачем

Решение владельца проекта (2026-09-21, приёмка v7.4): модель принимается с тем поведением, которое она показывает, но **всё, что задано извне, ведётся в реестре — какой параметр и что именно он меняет**. Внешний параметр — то, что модель не выводит сама: числовая константа, начальный запас, переключатель, тестовый множитель. В v7.4 их 245; из них 17 пар A/B несимметричны — это и есть весь набор величин, задающих различия колоний (сравнительные преимущества). Всё остальное различие поведения A и B — следствие.

## Две части

```text
инвентарь (генерируется из ModelJSON)          аннотации (ведутся вручную, версионируются)
  имя, вид, значение, колония, сектор,           роль / что меняет в поведении / доказательство /
  зеркало A↔B и флаг асимметрии,                 с какой версии / теги; applies_to_mirror — на пару;
  описание из модели, значения по сценариям      embedded_literals — литералы внутри формул
                       │                                      │
                       └──────────────┬───────────────────────┘
                                      ▼
                      parameter-registry.md / .json
                      сводка · несимметричные пары · аннотированные · полный инвентарь по секторам
                      покрытие · несимметричные без аннотации (долг) · аннотации на несуществующие имена (WARN)
```

## Команда

```cmd
PARAMETER_REGISTRY.cmd [путь\к\PARAMETER_ANNOTATIONS.json]
```

Без аргумента берёт `..\docs\PARAMETER_ANNOTATIONS.json`, если есть. Модель — единственный JSON в `input\model\`. Отчёт: `output\parameters-<timestamp>\parameter-registry.md/.json`. Команда информационная: exit code 0 даже при нулевом покрытии; долг виден в сводке.

## Файл аннотаций

```json
{
  "format": "orbital-economy-parameter-annotations-v1",
  "model": "…", "updated": "2026-09-21",
  "policy": "правило ведения",
  "parameters": {
    "A Ore Base Cost": { "role": "…", "effect": "…", "evidence": "…", "since": "v7.4 r2", "applies_to_mirror": true, "tags": ["comparative-advantage"] }
  },
  "embedded_literals": [
    { "element": "A Electronics Feedstock Buffer", "literal": "40 / [Metal per Electronics] × 40", "role": "…", "effect": "…" }
  ]
}
```

| Поле | Смысл |
|---|---|
| `role` (обязательно) | что это за величина и откуда взята |
| `effect` (обязательно) | что меняется в поведении модели при её изменении |
| `evidence` | прогон/документ, подтверждающий effect (Mode, день, число) |
| `applies_to_mirror` | аннотация распространяется на зеркальный параметр другой колонии |
| `embedded_literals` | константы, зашитые в формулы (например, `1200` в `IfThenElse(switch, 0.25 × 1200, 1200)`): инвентарь их не видит, поэтому они перечисляются вручную; отчёт проверяет, что элемент существует |

Аннотация на несуществующий примитив → `WARN` в отчёте (типичный случай: константа стала формулой и должна переехать в `embedded_literals`).

## Правило ведения

1. Новая константа в candidate → исполнитель даёт роль/эффект в отчёте, мы переносим в `PARAMETER_ANNOTATIONS.json` при приёмке.
2. Несимметричная пара A/B без аннотации — замечание к поставке (сводка показывает счётчик).
3. Изменение значения существующего параметра = изменение модели: только через change-policy (`definition_changed`), с обновлением `effect`/`evidence`.
4. Литерал, зашитый в формулу, — в `embedded_literals`; предпочтительно выносить в именованную константу при следующей версии.

## Baseline v7.4 r2

```text
Parameters: 245 (constants 153, initial stocks 61, switches 3, test wiring 28)
Annotated: 84/245; asymmetric A/B pairs: 17 (unannotated: 0); embedded literals listed: 7
```

Секторы: Electronics, Metal, Power, Transport, Trade, Labor, Switch, Test, Other. Отчёт — `../../docs/PARAMETER_REGISTRY.md`.

## Ограничения

- Инвентарь ловит только числовые `behavior.value` / `initial_value`; литералы в формулах и коэффициенты вида `^ 8`, `+ 0.001` — нет.
- Секторная классификация — по имени (regex), информативная.
- Аннотации — суждения, не выводы модели; `evidence` обязателен для параметров с тегом `comparative-advantage`.
