# Web reference workflow — Orbital Economy Lab v0.2.1

## Зачем он нужен

Web-экспорт теперь не является основным способом тестирования. Он нужен как независимая контрольная проверка, что локальный `simulation@9.0.0` воспроизводит web-расчёт той же ModelJSON.

## Принцип принадлежности результатов

Mode определяется из CSV автоматически по `Timed Test Mode`.

Модель **не определяется эвристически из чисел CSV**. Принадлежность web-партии модели фиксируется до экспорта через `web_batch_manifest.json`, содержащий SHA-256 активной ModelJSON.

Это предотвращает случайное сравнение результатов разных кандидатов, даже если отдельные сценарии у них дают похожие числа.

## Жизненный цикл партии

```text
PREPARE_WEB_CHECK.cmd
    ↓
input/web_reference/pending/
    web_batch_manifest.json
    source_model.json
    source_validation.json
    ↓
пользователь добавляет свежие *.csv
    ↓
RUN_LAB.cmd
    ↓
preflight
    ↓
local scenarios + comparison
    ↓
report
    ↓
output/run-.../web_reference/
```

## Preflight

При наличии CSV проверяются:

- manifest существует и читается;
- SHA-256 модели совпадает;
- каждый CSV позволяет определить Mode;
- Mode уникален;
- присутствуют все `expected_modes`;
- нет лишних Modes.

Если CSV отсутствуют полностью, web-check имеет статус `SKIPPED` и никак не ухудшает результат локальной валидации.

## Численное сравнение

Для каждого Mode проверяются:

- количество временных точек;
- `Time`;
- все колонки web CSV, которые должны быть найдены в локальной модели;
- maximum absolute difference;
- maximum relative difference;
- координаты максимальных различий.

`local-only` серии допустимы, потому что web может экспортировать подмножество всех серий модели.

`web-only` серии в партии той же модели считаются ошибкой интеграции/принадлежности.

## Архивирование

После обработанного запуска подготовленная партия копируется в:

```text
output/run-.../web_reference/
```

а `pending/` очищается и готовится к следующей контрольной партии.

Даже если cross-check дал FAIL, обработанная партия сохраняется вместе с отчётом, чтобы диагностика оставалась воспроизводимой.


## Fail-fast в v0.2.1

Если manifest, SHA-256, состав Modes или формат CSV не проходят preflight, стенд формирует FAIL-отчёт **до запуска симуляций**. Это позволяет проверять ошибочные партии быстро и исключает бессмысленный полный прогон 17 Modes при заведомо неверном reference batch.

Ручное тестирование таких ошибок не требуется: используйте `QA_SELF_TEST.cmd`.
