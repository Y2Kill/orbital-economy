1. INSTALL.cmd

4. COMPARE_SELF_TEST.cmd

ОБЫЧНАЯ ПРОВЕРКА ТЕКУЩЕЙ МОДЕЛИ
- положить ровно один ModelJSON в input\model\
- RUN_LAB.cmd

ФАКТИЧЕСКОЕ СРАВНЕНИЕ ACCEPTED ↔ CANDIDATE
- COMPARE_MODELS.cmd
- отвечает: ЧТО изменилось

ПРОВЕРКА СООТВЕТСТВИЯ CAPITAL LIFECYCLE KERNEL (статика, без simulation)
- LIFECYCLE_CONFORMANCE.cmd
- отвечает: реализует ли каждый сектор общий lifecycle-контракт
- NON_CONFORMING = HARD-блокер, policy не разрешает

АУДИТ СТРУКТУРЫ (статика, без simulation)
- STRUCTURE_AUDIT.cmd
- открытые границы: сколько потоков ещё создают капитал из ничего (объявленный closed-world контракт, сейчас 0)
- A/B-симметрия: зеркальность колоний (сейчас 0 расхождений, 0 исключений)

СБОРКА CANDIDATE ИЗ ПАТЧА (поставка исполнителя без стенда)
- APPLY_PATCH.cmd "delivery\model-patch.json" "input\model\candidate.json"
- база всегда reference\accepted\model\; см. docs\MODEL_PATCH_RU.md

РЕЕСТР ВНЕШНИХ ПАРАМЕТРОВ
- PARAMETER_REGISTRY.cmd  (аннотации: ..\docs\PARAMETER_ANNOTATIONS.json)
- что задано извне, какие пары A/B несимметричны, что аннотировано

ПРОВЕРКА CANDIDATE ПО CHANGE CONTRACT
- policy = единственный JSON в input\policy\
- CHECK_CANDIDATE.cmd
- отвечает: РАЗРЕШЕНЫ ЛИ обнаруженные изменения

Результаты:
output\policy-...\model-comparison.md/.json
output\policy-...\change-policy.md/.json

БЫСТРО ПЕРЕОЦЕНИТЬ УЖЕ ГОТОВЫЙ DIFF БЕЗ НОВОЙ SIMULATION
EVALUATE_POLICY.cmd "output\compare-...\model-comparison.json"

Поставляемый `change-policy-v7.5.1-strict.json` — default deny:
любое незаявленное изменение относительно accepted v7.5.1 r1 => POLICY FAIL.

Web CSV для обычной разработки НЕ нужны.
Для периодической web-проверки:
1. PREPARE_WEB_CHECK.cmd
2. экспортировать web CSV в input\web_reference\pending\
3. RUN_LAB.cmd

- default_action=deny рекомендуется сохранять
