# Задание 025 — ускорение аудита алгебраических петель (точное, без изменения результата)

Ветка: `task/025-loop-audit-speed` · Scope: `scope.json` рядом · Правила: контракт 1.9 §9, §9.2 п. 9 (контрольные точки и журнал), §9.4 · Порядок работы: `docs/tasks/README_RU.md`

## 1. Зачем

Аудит петель (`lab/src/loop_audit.js`) перебирает все 2^n комбинаций переключателей. На каждую комбинацию он заново выполняет три шага над всеми ~1300 переменными и потоками модели:

- переписывает формулы;
- вычисляет условия через `Function()`;
- строит граф и ищет сильно связные компоненты.

Время растёт вдвое с каждым переключателем модели. Сейчас это уже главный расход CI:

- самотест петель на раннере GitHub идёт 17 минут, локально на Windows — 35;
- весь набор самотестов вышел за 30-минутный лимит, лимит поднят до 60 (задача 024);
- модельная задача v7.7.9 добавит ещё один переключатель.

Задача — сделать аудит в десятки раз быстрее **без изменения результата**: отчёт аудита и детали комбинаций обязаны совпадать побайтно. Модель, validation и policy не меняются.

**Реализуемость проверена нами.** Прототип — `reference/loop_audit_prototype.js`. Это полная копия `loop_audit.js` с четырьмя сокращениями из §2. Он не нормативен по коду, но результат обязан совпасть, критерий N3. Сравнение — `reference/compare_loop_audit.mjs`.

| Модель | Комбинации / с петлями / разных петель | Сейчас | Прототип | Отчёт и детали |
|---|---|---|---|---|
| v7.6 r1 (`docs/model_v7_6_r1`) | 32 / 16 / 2 | 0.4 с | 0.07 с | побайтно равны |
| принятая v7.7.8 | 16384 / 0 / 0 | 65–80 с | 0.6–0.7 с (**×110**) | побайтно равны |
| скелет v7.7.9 (15 переключателей) | 32768 / 0 / 0 | 158 с | 1.5 с (**×105**) | побайтно равны |
| стресс: скелет v7.7.9, запросы энергии читают план того же шага (`reference/make_stress_model.mjs`) | 32768 / **16384** / **48** | 165 с | 7.9 с (×21) | побайтно равны |
| самотест петель целиком (`loop_qa.js`, Windows) | — | ~35 мин | **1 мин 3 с**, 15/15 PASS | — |

Потоки (`worker_threads`) не нужны. Они сделали бы `auditAlgebraicLoops` асинхронной, а её синхронно вызывают структурный аудит, conformance и самотесты. На 4 ядрах раннера это дало бы ×3–4, а точный алгоритм даёт ×100.

## 2. Четыре сокращения (все точные)

1. **Кандидаты.** Граф при пустом окружении содержит граф любой комбинации: все условия не решены, остаются обе ветки и ссылки самого условия. Любая петля любой комбинации лежит внутри нетривиальной сильно связной компоненты этого «объединённого» графа; петля на себя тоже считается. Перебор строит граф только на этих узлах — «кандидатах» — в прежнем порядке элементов.

   Почему это не меняет результат: компоненты и кратчайшие циклы зависят только от рёбер внутри компоненты, а `shortestCycle` и так ограничен её узлами. Итоговый список петель сортируется полностью.

   Пример: на v7.7.8 кандидатов 156 из 1327 узлов.
2. **Кэш решений условий.** Решение `decideCondition` кэшируется по подставленной строке. Это чистая функция строки.
3. **Статические формулы и кэш компонент.**
   - Формула без `IfThenElse` не зависит от переключателей; её текст вычисляется один раз.
   - Компоненты кэшируются по подписи графа — склеенному тексту всех формул кандидатов, зависящих от переключателей. Равные графы дают равные компоненты.
4. **Значимые переключатели.**
   - Переключатель может изменить граф кандидатов, только если на него ссылается условие `IfThenElse` в формуле кандидата. Имя сравнивается так же, как в `decideCondition`: `nameKey`. Такие переключатели — значимые.
   - Перебираются только значимые: 2^r масок, где незначимые биты равны 0. Каждая маска весит 2^(n−r) комбинаций; на эти веса умножаются `combinationsWithLoops` и `combinations` у каждой петли.
   - Маски перебираются по возрастанию с сохранением порядка битов. Поэтому первая маска, где появляется петля (её `example`), — та же, что при полном переборе.
   - `algebraicLoopCombinationDetails` перечисляет все 2^n масок, но компоненты берёт по проекции маски на значимые биты.

   Пример: на v7.7.8 значимых переключателей 10 из 14.

Проверки Modes (`modesWithLoops`) идут через тот же кэш. Окружение сценария содержит и непереключательные значения; подпись это учитывает.
