## 1. Зачем

Финансовый слой, промежуточный шаг. Основание:
- решения владельца от 2026-10-12;
- прототипы — `docs/research/FINANCE_PROTOTYPE_2026-10-12_RU.md`;
- анализ Morris — `docs/research/SENSITIVITY_2026-10-10_RU.md`, третий проход.

Сейчас зарплата входит только в себестоимость металла и электроники. В ценах руды, энергии и еды труда нет, а спрос от цены не зависит. Поэтому зарплата B дрейфует: дешевеющий труд B ничего не меняет в экономике.

Два механизма под одним переключателем `Wage Pricing Enabled`:
1. **Зарплата в ценах.** Цены, в которых нет труда, следуют за зарплатой своего региона пропорционально:
   `новая = старая × Max(1 + доля труда × (зарплата / стартовая − 1), 1e-6)`.
   - Доля труда задаётся в декларации по регионам: стартовая стоимость труда / стартовая цена, не больше 1.
   - На старте цены не меняются.
2. **Спрос от цены.** Конечный спрос на металл и электронику умножается на `Max(цена / опорная, 1e-6) ^ (−η)`.
   - Опорная цена задаётся в декларации по регионам.
   - η — параметр узла (0.5).

Каждая замена имеет вид `IfThenElse([Wage Pricing Enabled] = 1, новое, старое)`. При 0 ни один прежний ряд не меняется. Узел не создаёт запасов и потоков: граница модели не меняется.

Задача:
- тип узла `wage_pricing` (Lab **v0.9.19**);
- плагин validation `wage_pricing`;
- `node_qa`: узел лежит поверх всех прежних, включая `labor_market` и `food`.

**Модель, validation и policy не меняются.** Первым применением станет модельная задача v7.7.15 (037).

## 2. Узел `wage_pricing`

### 2.1 Декларация (строгая схема; незнакомое поле — ошибка с путём)

См. `fixtures/wage_pricing.json`:

```json
{
  "type": "wage_pricing", "version": 1, "colonies": ["A", "B"], "switch": "Wage Pricing Enabled",
  "parameters": { "Price Demand Elasticity": 0.5 },
  "inputs": { "wage": "{C} Wage", "initial_wage": "{C} Initial Wage" },
  "prices": [ { "name": "Ore", "target": "{C} Ore Price", "labor_share": { "A": 1, "B": 0.5 } }, … ],
  "demand": [ { "name": "Metal", "target": "{C} Effective Local Base Demand", "price": "{C} Market Price",
                "elasticity": "Price Demand Elasticity", "reference_price": { "A": 25.9, "B": 34.46 } }, … ]
}
```

Правила декларации:
- `version` = 1; регионов ≥ 2, без повторов; `switch` — имя, которого нет в базе;
- `parameters` — непустой объект, значения конечные и > 0;
- `inputs` — ровно `wage` и `initial_wage`; оба должны существовать для каждой колонии;
- `prices` и `demand` — непустые массивы:
  - `name` — непустое, без повторов внутри массива;
  - `target` — без повторов;
- `prices[].labor_share` — ключ для каждой колонии, и только для них; значение в [0, 1];
- `demand[].reference_price` — ключ для каждой колонии, и только для них; значение > 0;
- `demand[].elasticity` — один из ключей `parameters`;
- `target` должен существовать и быть VARIABLE с формулой или значением; `demand[].price` должна существовать — для каждой колонии;
- имя, которое создал бы генератор, уже есть в базе — ошибка с именем. Отсюда имя опорной цены `… Demand Reference Price`: `X Electronics Reference Price` в модели уже занято.

### 2.2 Раскрытие

Имена, формулы и значения — **как в прототипе** (`expandWagePricing`).

**Общие элементы:** переключатель (VARIABLE, 0) и параметры.

**На регион X:**
- `X Relative Wage Change` = `[X Wage] / Max([X Initial Wage], 1e-6) − 1`;
- на каждую цену:
  - константа `X {name} Labor Share`;
  - замена цены: `IfThenElse(SW = 1, (старая) × Max(1 + [X {name} Labor Share] × [X Relative Wage Change], 0.000001), старая)`;
- на каждый спрос:
  - константа `X {name} Demand Reference Price`;
  - `X {name} Price Demand Factor` = `Max([цена] / [опорная], 0.000001) ^ (−[эластичность])`;
  - замена цели: `IfThenElse(SW = 1, (старая) × [фактор], старая)`.

Связи — по ссылкам `[…]` новых формул и замен, без дублей.

**Почему пропорционально, а не прибавкой.** Стоимость труда в единице еды (0.15 × зарплата: 15–21) больше всей цены еды (индекс около 10). Прибавка «норма × (зарплата − стартовая)» обрушивает цену еды в B, когда её зарплата падает, и население переезжает в B. Подробности — в отчёте о прототипе.

### 2.3 Фрагменты validation

`validation` раскрытия:
- `wage_pricing_instances` — на регион: `name`, `colony`, `wage`, `initial_wage`, `relative_wage_change`;
  - `prices[]` — `target`, `labor_share`;
  - `demand[]` — `target`, `price`, `reference_price`, `factor`, `elasticity`;
- `wage_pricing_switch`.

Слияние — как у `labor_market`: один плагин `wage_pricing` с `rel_tol` (по умолчанию 1e-9), `switch`, `instances`. Повтор экземпляра с другим определением — ошибка.

Структурные фрагменты не нужны: потоков нет, пар нет, драйверы P6 не меняются.

### 2.4 Плагин `wage_pricing`

**Статика:**
- все названные колонки существуют;
- `labor_share` — числовая константа в [0, 1];
- опорная цена — числовая константа > 0;
- эластичность — числовая константа > 0.

**Runtime**, во всех точках:
- `relative_wage_change` = зарплата / стартовая − 1 (относительный допуск);
- фактор спроса = Max(цена / опорная, 1e-6)^(−η) (относительный допуск);
- цены `prices[].target` > 0.

Ошибка — FAIL с именем экземпляра и колонки.
