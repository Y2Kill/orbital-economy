## 1. Зачем

Последнее исключение Planet v1 P2 — добыча энергоресурса (`X Power Resource Extraction Rate`): у неё **нет мощности вовсе**, добыча идёт за спросом с запасом ×1.1. Руду и реголит мы перевели на простой капитал заменой константы мощности внутри готовой переменной мощности (`capacity_output.replaces`). Здесь заменять нечего, а добавить переменную мощности руками в том же патче нельзя: секция `nodes` раскрывается относительно base **до** явных секций, поэтому узел её не увидит.

Задача — два расширения типа узла `simple_capital` в генераторе (Lab v0.9.11). **Модель, validation и policy не меняются.** Первым применением станет задача по модели v7.7.7 (шахта энергоресурса).

## 2. Что сделать

### 2.1 `capacity_output.cap`

- Схема: `capacity_output` — `variable` и **ровно одно** из `replaces` / `cap`. `cap` допустим только у `simple_capital` и только со значением `"smooth"`; иначе — ошибка с путём. У `capital_lifecycle` — как сейчас (`replaces` обязателен).
- Раскрытие при `cap: "smooth"`, для каждой колонии X и сектора S:
  - новый VARIABLE `X S Uncapped Output` = **дословно** прежняя формула переменной;
  - замена переменной: `IfThenElse([switch] = 1, [X S Uncapped Output] / (1 + ([X S Uncapped Output] / ([X S Capacity] + 0.001)) ^ 8) ^ 0.125, <прежняя формула дословно>)` — та же форма насыщения, что у добычи руды (`X Mining Rate`);
  - `X S Uncapped Output` входит в список генерируемых имён (конфликт с base — ошибка, снятие узла в самотесте её удаляет).
- При `replaces` раскрытие не меняется ни на байт (существующие декларации `model/nodes/*.json`).

### 2.2 `sizing.signal.initial` по колониям

- Число — одно значение для всех колоний (как сейчас). Объект — ключи ровно по `colonies`: отсутствующая колония или лишний ключ — ошибка с путём; значения — конечные числа.
- Сток сигнала колонии X стартует со своего значения.
