# Задание 033 — тип узла `labor_market`: спрос по населению, гибкая зарплата, ограничение выпуска трудом

Ветка: `task/033-labor-market-node` · Scope: `scope.json` рядом · Правила: контракт 1.9 §9, §9.2 п. 9 (контрольные точки и журнал), §9.4 · Порядок работы: `docs/tasks/README_RU.md`

## 1. Зачем

Planet v2, шаг 3 — **замкнуть связи** «население — потребление — труд — зарплата — производство». Основание:
- решения владельца от 2026-10-04 и 2026-10-10;
- прототип — `docs/research/CLOSURE_PROTOTYPE_2026-10-09_RU.md`;
- внешний обзор 2026-10-09.

Три механизма под одним переключателем `Labor Market Enabled`:
1. **Спрос по населению:** базовый спрос региона на металл и электронику = норма на душу (уровень A: 16/28 и 20/28) × население.
2. **Гибкая зарплата:** запас, который следует за напряжённостью рынка труда (спрос на труд / рабочая сила):
   - цель 0.95;
   - скорость 10 % в год;
   - нижняя граница — 30 % стартовой.
3. **Ограничение выпуска трудом** (предохранитель): скорости всех процессов региона × доступность труда = min(1, рабочая сила / спрос на труд).
   - Спрос на труд — потребность при **неурезанном** выпуске, сглаженный запас (10 дней).
   - Вход и выход процесса масштабируются вместе.

Спрос от дохода домохозяйств отложен до финансового слоя: в прототипе он разгоняет спираль зарплат.

Каждая замена формулы имеет вид `IfThenElse([Labor Market Enabled] = 1, новое, старое)`. При 0 ни один прежний ряд не меняется.

Задача:
- тип узла `labor_market` (Lab **v0.9.18**);
- плагин validation `labor_market`;
- `node_qa`: этот узел лежит поверх всех прежних, включая `food`.

**Модель, validation и policy не меняются.** Первым применением станет модельная задача v7.7.13 (034).

## 2. Узел `labor_market`

### 2.1 Декларация (строгая схема; незнакомое поле — ошибка с путём)

См. `fixtures/labor_market.json`:

```json
{
  "type": "labor_market", "version": 1, "colonies": ["A", "B"], "switch": "Labor Market Enabled",
  "parameters": { "Metal Demand per Capita": …, "Electronics Demand per Capita": …, "Wage Adjustment Rate": …,
                  "Target Labor Tightness": …, "Wage Floor Share": …, "Labor Demand Signal Time": … },
  "inputs": { "population": "{C} Population", "population_initial": "{C} Population Initial",
              "participation": "Labor Participation Share", "labor_force": "{C} Labor Force",
              "labor_requirement": "{C} Total Labor Requirement", "wage": "{C} Wage" },
  "demand": [ { "target": "{C} Local Base Demand", "per_capita": "Metal Demand per Capita" }, … ],
  "rates": [ "{C} Mining Rate", …, "{C} Food Production" ]
}
```

Правила декларации:
- `parameters` — ровно 6 ключей фикстуры; значения конечные и > 0;
- регионов ≥ 2;
- `switch` — имя, которого нет в базе;
- все `inputs`, `demand[].target`, `rates` должны существовать для каждой колонии;
- `demand[].per_capita` — один из ключей `parameters`;
- `population_initial`, `participation` и `wage` — числовые константы в базе;
- `demand[].target` — числовая константа или формула;
- `rates` без повторов;
- имя, которое создал бы генератор, уже есть в базе — ошибка с именем.

### 2.2 Раскрытие

Имена, формулы и стартовые значения — **как в прототипе** (`expandLaborMarket`).

**Общие элементы:** переключатель (VARIABLE, 0) и параметры.

**На регион X:**
- STOCK `X Labor Demand Signal` (старт = начальное население × доля трудоспособных) с потоками из ∅ / в ∅;
- `X Labor Availability`, `X Labor Demand`, `X Labor Tightness`;
- `X Initial Wage` (= прежняя константа зарплаты) и STOCK `X Flexible Wage` с потоками `X Wage Increase` / `X Wage Decrease` (из ∅ / в ∅);
- на каждый элемент `demand` — `X External <имя без X>` (= прежняя константа), если цель была числом.

**Замены** (24 при двух регионах), все в виде `IfThenElse([switch] = 1, …, <старое>)`:
- на регион:
  - зарплата → `[X Flexible Wage]`, старая ветка `[X Initial Wage]`;
  - 2 цели спроса → `[норма] * [X Population]`, старая ветка — `[X External …]`;
  - 9 скоростей → `(<старое>) * [X Labor Availability]`.

**Правило:** числовая константа не вставляется в обёрнутую формулу — она уходит в именованный параметр. Иначе формулы A и B перестают быть зеркальными, и падает проверка симметрии. Мы на этом споткнулись при подготовке.

**Связи** — на каждую ссылку добавленных и заменённых формул, без дублей.

### 2.3 Фрагменты validation и слияние

Состав — как `validation` в `expandLaborMarket`.

- **`open_boundaries`:** `? Wage Increase` и `? Wage Decrease` → `information_signal`; сигналы спроса на труд попадают под `* Signal Increase/Decrease`.
- **`planet_closure.demand_drivers` (P6)** — **переобъявление.**
  - В Planet v1 конечный спрос задавали внешние константы `{C} Local Base Demand` и `{C} Electronics Local Base Demand`.
  - Теперь спрос зависит от населения (запаса), и прежние драйверы перестают быть внешними. Без этого `planet_v1` падает: «demand driver … depends on a STOCK».
  - Фрагмент заменяет их в `parameters` на нормы на душу из `demand[].per_capita` и записывает `reason` про Planet v2.
- **Новый плагин `labor_market`:**
  - экземпляр на регион — `name`, `colony`, `availability`, `labor_force`, `labor_demand_signal`, `tightness`, `wage`, `initial_wage`, `rates` [имена], `demand` [{`target`, `per_capita`, `population`}];
  - общие поля `switch`, `floor` (имя параметра).
- **Слияние:**
  - создаёт плагин и категории, если их нет;
  - повторное слияние идемпотентно;
  - если ничего не меняется — файл копируется побайтно.

### 2.4 Плагин `labor_market`

**Статика** (этап conformance, HARD):
- типы ролей: `availability`, `tightness`, `initial_wage` — VARIABLE; `labor_demand_signal`, `wage` — STOCK;
- каждая скорость из `rates` в обёртке переключателя читает `availability`;
- каждая цель `demand` в обёртке читает свою норму и население;
- `availability` читает `labor_force` и `labor_demand_signal`.

**Прогон:**
- 0 ≤ доступность ≤ 1;
- `wage` ≥ доля × `initial_wage` (с `abs_tol`);
- в точках, где переключатель = 1, — тождество спроса: цель = норма × население (относительный допуск);
- где переключатель = 0 — доступность = 1.
