# Задание 031 — тип узла `food`: еда, фермы на земле, торговля по потребности, приоритеты в энергии и транспорте

Ветка: `task/031-food-node` · Scope: `scope.json` рядом · Правила: контракт 1.9 §9, §9.2 п. 9 (контрольные точки и журнал), §9.4 · Порядок работы: `docs/tasks/README_RU.md`

## 1. Зачем

Planet v2, шаг 2. Основа — решения владельца от 2026-10-04/05 и прототип (`docs/research/FOOD_PROTOTYPE_2026-10-05_RU.md`). У регионов появляется еда. Её производят фермы — капитал на земле региона. Фермам нужны энергия, оборудование и труд. Еду едят люди, а регионы торгуют ею по потребности. Нехватка еды бьёт по людям: падает уровень жизни, растёт смертность, снижается рождаемость, а вслед за этим меняется миграция.

Шаг включается переключателем `Food Enabled`. При 0 ни один прежний ряд не меняется: каждая замена формулы обёрнута в `IfThenElse([Food Enabled] = 1, новое, старое)`, как у прежних узлов с переключателем.

Механика повторяется на каждый регион, а торговля — на каждую упорядоченную пару регионов. Поэтому это работа генератора узлов. Задача:
- тип узла `food` (Lab **v0.9.17**);
- плагин validation `food`;
- правка `node_qa`: узел с переключателем над узлами без переключателя (§3.3).

**Модель, validation и policy не меняются.** Первым применением станет модельная задача v7.7.12 (032).

## 2. Узел `food`

### 2.1 Декларация (строгая схема; незнакомое поле — ошибка с путём)

См. `fixtures/food.json`:

```json
{
  "type": "food", "version": 1, "colonies": ["A", "B"], "switch": "Food Enabled",
  "land": { "A": 22, "B": 60 },
  "parameters": { …20 ключей… },
  "inputs": {
    "population": "{C} Population", "population_initial": "{C} Population Initial",
    "capital_goods": { "inventory": …, "demand": …, "fulfillment": … },
    "energy": { "total_request": …, "supply": …, "priority_request": …, "priority_fulfillment": …, "fulfillment": … },
    "labor_total": "{C} Total Labor Requirement", "travel_time": "Travel Time"
  },
  "transport": { "capacity": …, "capacity_readers": [ … ], "load_readers": [ { "name": …, "term": … } ] },
  "people": { "living": …, "living_columns": [ { "column": …, "weight": "<имя параметра>" } ], "deaths": …, "births": …,
              "price_index": { "name": …, "terms": 2 } }
}
```

Правила декларации:
- `parameters` — ровно 20 ключей фикстуры; значения конечные и > 0;
- `land` — ключи ровно по `colonies`, значения > 0;
- регионов ≥ 2;
- `switch` — имя, которого нет в базе;
- все `inputs.*`, `transport.*`, `people.*` должны существовать в базе (для `{C}` — для каждой колонии);
- `transport.capacity_readers` должны читать `[capacity]`, `load_readers[].name` — свой `term`, иначе ошибка с именем;
- `living_columns[].weight` — один из ключей `parameters`; `price_index.terms` — целое ≥ 1;
- имя, которое создал бы генератор, уже есть в базе — ошибка с именем.

### 2.2 Раскрытие

Имена, формулы и стартовые значения — **как в прототипе**: `expandFood` в `reference/food_node_prototype.mjs`.

**Общие:**
- переключатель (VARIABLE, 0);
- параметры;
- `X Farm Land Capacity`;
- `Food Transport Capacity`, `Food Transport Scale`, `Food Transport Load`, `Transport Goods Capacity`, `Planet Food Production`.

**На регион X:**
- запас еды и сглаженный спрос;
- доля обеспечения, потребление, цена;
- план производства и его сглаженный сигнал;
- ферма: мощность, эффективная мощность под мягким лимитом земли, желаемое расширение, расширение за оборудование, износ;
- энергия фермы — в приоритетной группе;
- производство;
- труд фермы;
- потребность в импорте и экспортируемый излишек.

**На упорядоченную пару X → Y:**
- сигнал заказов `X to Y Food Export Signal` — STOCK с потоками из ∅ / в ∅;
- запрошенная отгрузка;
- груз в пути (STOCK);
- отгрузка `Food Dispatch X to Y`: запас X → груз;
- прибытие `Food Arrival X to Y`: груз → запас Y.

**Стартовое состояние** считается из базы по `population_initial` и `land`:
- регион с нехваткой земли обрабатывает её всю;
- регионы с запасом земли кормят себя и покрывают нехватку пропорционально свободной земле;
- эта поставка уже в пути: груз = поток × время в пути.

**Замены** (25 при двух регионах), все в виде `IfThenElse([switch] = 1, …, <старое>)`:
- на регион — по одной для:
  - общий запрос энергии, выдача энергии, приоритетный запрос;
  - спрос на оборудование;
  - потребность в труде;
  - уровень жизни, смерти, рождения;
  - индекс цен;
- общие — 2 замены для `capacity_readers` и 5 для `load_readers`.

**Связи** — на каждую ссылку добавленных и заменённых формул, без дублей.

### 2.3 Фрагменты validation и слияние

Состав — как `validation` в `expandFood`.

**`open_boundaries`:**
- новая категория `agriculture` (`direction: source`, `closed_world: true`, `? Food Production`);
- `? Food Consumption` → `final_consumption`;
- `? Farm Expansion`, `? Farm Capital Goods Consumption` → `capital_transformation`;
- `? Farm Depreciation` → `capital_retirement`;
- пары преобразования «расширение фермы ↔ расход оборудования» с runtime-тождеством, как у простого капитала.

Сигналы еды попадают под существующие шаблоны `* Signal Increase` / `* Signal Decrease`.

**`planet_closure`:**
- категория `agriculture` в `process_categories`;
- процесс `farming` (`kind: transformation`):
  - мощность — `simple`, `{C} Farm Capacity`;
  - энергия — `requests`, сигнал `{C} Food Production Signal`, `fulfillment` — приоритетная доля;
  - труд — `declared`, `requirement` `{C} Farming Labor Requirement`.

**Новый плагин `food`:** экземпляр на регион — `name`, `colony`, `inventory`, `production`, `consumption`, `demand`, `fulfillment`, `farm_capacity`, `farm_effective_capacity`, `land`, `dispatch` [потоки], `arrival` [потоки]. Плюс общий раздел `transport` — `load`, `capacity`, `max_share` (имя параметра).

**Слияние:**
- создаёт плагин и категорию, если их нет;
- повторное слияние идемпотентно;
- если ничего не меняется — файл копируется побайтно.

### 2.4 Плагин `food`

**Статика** (этап conformance, HARD):
- типы ролей: `inventory`, `farm_capacity` — STOCK; `production`, `consumption`, `dispatch`, `arrival` — FLOW;
- направления потоков:
  - `production` — из ∅ в `inventory`;
  - `consumption` — из `inventory` в ∅;
  - `dispatch` — из `inventory`;
  - `arrival` — в `inventory`;
- у каждого `dispatch` X → груз есть `arrival` того же груза в другой объявленный регион;
- `production` читает `farm_effective_capacity`, а она читает `farm_capacity` и `land`.

**Прогон:**
- запас ≥ 0, потоки ≥ 0;
- 0 ≤ доля обеспечения ≤ 1;
- потребление ≤ спрос (с `abs_tol`);
- эффективная мощность ≤ земля;
- производство ≤ эффективная мощность (с `abs_tol`);
- груз еды на транспорте ≤ `max_share` × мощность (с `abs_tol`).

### 3.3 Узел с переключателем над узлами без переключателя

После задачи 032 `food` будет в принятой модели. Он оборачивает формулы, созданные `population` (уровень жизни, смерти, рождения, индекс цен) и `labor` (потребность в труде), и читает выходы `population`.

Цепочка `switchlessLayers` в `node_qa` (задача 030) снимает `labor` и `population` прямо с принятой модели. Когда над ними лежит узел с переключателем, это невозможно.

Требование:
- цепочка узлов без переключателя начинается с модели, из которой уже сняты все узлы с переключателем, **читающие или оборачивающие** их элементы;
- остальные узлы с переключателем остаются, как сейчас.

Случай 52 проверяет это на модели «принятая + еда» без ожидания задачи 032.

Если узел уже есть в принятой модели (после 032), случаи 46–50 работают на его слое — как у прежних узлов.
