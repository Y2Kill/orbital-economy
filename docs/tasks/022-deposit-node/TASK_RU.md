## 2. Узел `deposit`

### 2.1 Декларация (строгая схема; незнакомое поле — ошибка с путём)

```json
{
  "type": "deposit", "version": 1, "colonies": ["A", "B"], "switch": "Deposits Enabled",
  "resources": [ {
    "resource": "Ore",
    "extraction": { "flow": "{C} Mining", "rate": "{C} Mining Rate" },
    "initial": { "undiscovered": { "A": …, "B": … }, "proven": { "A": …, "B": … } },
    "parameters": { "Target Reserve Life": …, "Exploration Time": …, "Capital Goods per Discovery": …, "Depletion Buffer Days": … },
    "signal": { "name": "{C} Ore Extraction Signal", "initial": { "A": …, "B": … }, "adjustment_time": { "name": "…", "value": … } },
    "backing": [ { "good": "Capital Goods", "fulfillment": "{C} …", "inventory": "{C} …", "demand": "{C} …" } ],
    "planet_process": "mining"
  }, … ]
}
```

Один узел — слой месторождений планеты для нескольких ресурсов, **один переключатель** (одна модельная ступень — один переключатель регрессии). Обязательны все поля; параметры — ровно четыре перечисленных, плюс `<good> per Discovery` для каждого `backing`; `initial.*` и `signal.initial` — ключи ровно по `colonies`.

### 2.2 Раскрытие (имена и формулы — как в прототипе; R — ресурс, X — колония)

- переключатель; `R Deposit <Parameter>`; время подстройки сигнала;
- `X R Undiscovered Resource Initial`, `X R Proven Reserves Initial` — VARIABLE-параметры;
- STOCK `X R Undiscovered Resource`, `X R Proven Reserves` с `initial_value` = ссылка на свой параметр;
- сглаженный сигнал добычи `X R Extraction Signal` (сток + Increase/Decrease, по `extraction.rate`) — цель разведки читает **сток**, иначе разведка → спрос на оборудование → производство → металл → добыча замыкает петлю;
- `X R Target Proven Reserves` = сигнал × `Target Reserve Life`; `X R Reserve Gap` = max(цель − разведанное, 0); `X R Discovery Factor` = неразведанное / его начальное; `X R Desired Exploration` = `IfThenElse(switch, gap / Exploration Time × Discovery Factor, 0)`;
- FLOW `X R Exploration`: неразведанное → разведанное = `IfThenElse(switch, desired × Min(fulfillment…), 0)`;
- FLOW `X R Exploration <good> Consumption`: склад блага → ∅ = `IfThenElse(switch, Exploration × <good> per Discovery, 0)`; спрос на благо дополняется желаемой разведкой (вложенный `IfThenElse`, старая ветка дословно);
- `X R Deposit Unlimited Rate` = прежняя формула скорости дословно; скорость = `IfThenElse(switch, U / (1 + (U / (Proven / Depletion Buffer Days + 0.001)) ^ 8) ^ 0.125, прежняя)` — мягкий потолок истощения той же формы, что мощность;
- **поток добычи `extraction.flow` перенаправляется: `from` = `X R Proven Reserves`** (было `∅`; только из `∅`, иначе ошибка).

Точку подключения потока переключателем не выключить: при выключенном переключателе поток тянет разведанные запасы, но его значение прежнее, и ряды Modes 0–… не меняются, пока запасов хватает (разведанное на старте ≈ 10 лет добычи против 3 лет горизонта). Это надо сказать в `NODES_RU.md` прямо.

### 2.3 Патч: перенаправление потока

Генератор возвращает новую секцию патча **`retarget_flows`**: `[{ name, from, to }]` (`null` — `∅`). `APPLY_PATCH` применяет её после `add_elements` (цель может быть новым стоком): поток и стоки обязаны существовать; перенаправляемый поток не может одновременно добавляться или перенаправляться дважды; узел и явная секция не могут трогать один поток. Секция допустима и в явном патче (строгая схема, как у остальных). Сравнение моделей видит перенаправление как изменение определения потока — в policy это `definition_changed`.

### 2.4 Фрагменты validation и слияние

- `planet_closure`: у процесса `planet_process` — `deposit: { kind: "stock", stock: "{C} R Proven Reserves" }`;
- `open_boundaries`: новая категория `exploration_expenditure` (`direction: sink`, `closed_world: true`, «capital goods spent on resource exploration leave the economy») с именами `? R Exploration <good> Consumption`; потоки сигнала попадают в существующую `information_signal`;
- новый плагин validation **`deposit`**: экземпляр на ресурс и колонию (`name`, `resource`, `undiscovered`, `proven`, `exploration`, `extraction`, `signal`, `consumption`). **Статика** (в этапе conformance, HARD как `simple_capital`): типы ролей; `extraction` — FLOW из `proven`; `exploration` — FLOW `undiscovered → proven`; цель разведки читает `signal`, и это STOCK; каждый расход читает `exploration`. **Прогон**: оба стока ≥ 0, разведка и расходы ≥ 0, тождество «расход = разведка × норма» (runtime identity);
- `expand-nodes --validation` и `mergeNodeValidation` создают плагин и категорию, если их нет; повторное слияние идемпотентно; если слияние ничего не меняет — файл копируется побайтно (как сейчас).
