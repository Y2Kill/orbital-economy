# Задание 029 — тип узла `population`: население регионов, рождения, смерти, миграция и учёт труда

Ветка: `task/029-population-node` · Scope: `scope.json` рядом · Правила: контракт 1.9 §9, §9.2 п. 9 (контрольные точки и журнал), §9.4 · Порядок работы: `docs/tasks/README_RU.md`

## 1. Зачем

Planet v2, шаг 1 — решения владельца от 2026-10-04 (`docs/research/POPULATION_PROTOTYPE_2026-10-04_RU.md`, `docs/PLANET_V1_CONTRACT_RU.md` §6, решение 6 «регионы, а не колонии»). У каждого региона появляется население:
- рождения и смерти (естественный рост);
- миграция между регионами по привлекательности: реальная зарплата × шанс найти работу × уровень жизни;
- учёт труда: рабочая сила, занятость, безработица, нехватка рук.

**Шаг 1 — только учёт.** Население не влияет на экономику:
- выпуск трудом не ограничен;
- спрос остаётся внешним драйвером P6;
- зарплаты фиксированы;
- уровень жизни на этом шаге — только доля выполнения по энергии. Потребление на душу без связи «население → спрос» — артефакт (эксперименты, серия 1).

Поэтому **переключатель не нужен**: ни один прежний ряд не меняется. Связь «население → спрос», гибкая зарплата и еда — следующие шаги.

Одна механика повторяется на каждый регион, а миграция — на каждую упорядоченную пару регионов. Это работа генератора узлов, и тот же узел понадобится будущему генератору регионов. Задача:
- тип узла `population` (Lab v0.9.16);
- плагин validation `population`.

**Модель, validation и policy не меняются.** Первым применением станет модельная задача v7.7.11 (030).

## 2. Узел `population`

### 2.1 Декларация (строгая схема; незнакомое поле — ошибка с путём)

```json
{
  "type": "population", "version": 1, "colonies": ["A", "B"],
  "initial": { "A": 28, "B": 8.5 },
  "parameters": {
    "Population Birth Rate": …, "Population Base Death Rate": …, "Death Living Standard Sensitivity": …,
    "Labor Participation Share": …, "Migration Max Rate": …, "Migration Gap Sensitivity": …,
    "Attractiveness Perception Time": …, "Attractiveness Wage Weight": …, "Attractiveness Jobs Weight": …,
    "Attractiveness Living Weight": …, "Reference Real Wage": …
  },
  "inputs": {
    "wage": "{C} Effective Wage",
    "labor_requirement": "{C} Total Labor Requirement",
    "prices": [ { "price": "{C} Market Price", "reference": "{C} Reference Metal Price" }, … ],
    "living": [ { "name": "Energy", "column": "{C} Energy Fulfillment Ratio", "weight": 1 } ]
  }
}
```

Правила декларации:
- `parameters` — ровно перечисленные 11 ключей; значения конечные, > 0 (веса ≥ 0);
- `initial` — ключи ровно по `colonies`, значения > 0;
- все `inputs.*` должны существовать в базе для каждой колонии;
- `prices` — непустой; `living` — непустой, `name` — уникальные, `weight` ≥ 0;
- регионов ≥ 2;
- имя, которое создал бы генератор, уже есть в базе — ошибка с именем.

### 2.2 Раскрытие (имена и формулы — как в прототипе; X, Y — регионы)

**Общие элементы:**
- параметры — по одному VARIABLE на ключ;
- `Living <name> Weight`;
- `Planet Population` — сумма населений.

**На регион X:**
- `X Population Initial` (VARIABLE) и STOCK `X Population` с `initial_value` = ссылка на него;
- FLOW `X Births`: ∅ → население = население × рождаемость;
- FLOW `X Deaths`: население → ∅ = население × базовая смертность × Max(уровень жизни, 0.05)^(−чувствительность);
- `X Labor Force` = население × доля трудоспособных;
- `X Employment` = Min(потребность в труде, рабочая сила);
- `X Employment Rate`, `X Unemployment`, `X Labor Shortage`;
- `X Price Index` — среднее отношений цен к опорным;
- `X Real Wage` = зарплата / индекс цен;
- `X Living Standard` — произведение (Max(колонка, 1e-6))^вес по `living`;
- `X Attractiveness` = (реальная зарплата / опорная)^w × Max(занятость, 1e-6)^w × уровень жизни^w;
- STOCK `X Perceived Attractiveness` (старт 1) с FLOW `… Increase` / `… Decrease` из ∅ / в ∅ (сглаживание с временем восприятия).

**На упорядоченную пару X → Y:**
- `Attractiveness Gap X to Y`;
- FLOW `Migration X to Y`: `X Population` → `Y Population` = население X × макс. скорость × Min(Max(разрыв, 0) × чувствительность, 1).

**Связи:** на каждую ссылку, без дублей.

### 2.3 Фрагменты validation и слияние

- `open_boundaries`:
  - в `information_signal` — `? Perceived Attractiveness Increase` и `? Perceived Attractiveness Decrease`;
  - новые категории `demography_births` (`direction: source`, `closed_world: true`, `? Births`) и `demography_deaths` (`sink`, `? Deaths`);
- **новый плагин `population`**: экземпляр на регион — `name`, `colony`, `population`, `births`, `deaths`, `immigration` [потоки], `emigration` [потоки], `labor_force`, `employment`, `labor_requirement`, `participation` (имя параметра);
- слияние создаёт плагин и категории, если их нет; повторное слияние идемпотентно; если ничего не меняется — файл копируется побайтно.

### 2.4 Плагин `population`

- **Статика** (этап conformance, HARD):
  - типы ролей: `population` — STOCK; потоки — FLOW;
  - `births` — из ∅ в население, `deaths` — из населения в ∅;
  - каждый поток миграции идёт из населения своего региона в население другого, объявленного в том же плагине; у каждого потока есть зеркальная запись (`emigration` X ↔ `immigration` Y);
  - `labor_force` читает `population` и `participation`;
  - `employment` читает `labor_force` и `labor_requirement`.
- **Прогон**:
  - население ≥ 0, все потоки ≥ 0;
  - занятость ≤ рабочая сила и ≤ потребность в труде (с `abs_tol`);
  - рабочая сила = население × значение доли трудоспособных (относительный допуск);
  - **сохранение людей при миграции:** сумма всех эмиграций = сумме всех иммиграций в каждой точке.
