## Ключевые проектные решения (почему так)

- **Точное воспроизведение, не tolerance.** Прежние Modes обязаны давать `max abs diff = 0` относительно предыдущего accepted. Любое ненулевое отличие — либо найденная причина, либо отклонение поставки.
- **Движок заморожен** на `simulation@9.0.0` до нового golden cross-check.
- **Validation ≠ policy.** Validation отвечает «корректна ли модель», policy — «разрешено ли отличие от baseline». Policy не может ослабить validation и не подгоняется постфактум.
- **Kernel ≠ sector policy.** Kernel — физическая структура капитала (одинакова), policy — сколько мощности нужно (отраслевая).
- **Legacy-switch не распространяется.** Каждый новый слой получает свой переключатель (`Capital Lifecycle Enabled`, `Intermediate Inputs Enabled`, `Capital Goods Enabled`, `Power Resource Enabled`), старые Modes выключают его явно.
- **Сначала вширь до самостоятельной планеты, потом разбиение** (решение 2026-09-21). Измеряется счётчиком closed-world нарушений `open_boundaries`: 7 (v7.4) → 1 (v7.5) → 0 (v7.5.1). Ноль означает выполнение объявленного контракта границы расширения капитала, а не завершённость Planet v1.
- **Модель отражает поведение — так тому и быть; внешние параметры — под учёт** (решение 2026-09-21 при приёмке v7.4). Переворот специализации не «лечится» калибровкой; каждый внешний параметр аннотируется: какой и что меняет. Несимметричная пара A/B без аннотации — долг.
- **Исполнитель без стенда** (чат-модель): поставка патчем, итерации через нас; спецификация проверяется skeleton-патчем до выдачи — и skeleton должен покрывать обе колонии, а не только ту, где эффект заведомо виден.
- **Сигнал цены читает сглаженное состояние, а не мгновенный спрос** (урок v7.6): иначе цена → спрос → нормирование → цена замыкается в алгебраическую петлю, которую статические проверки не видят.
- **Парное тождество проверяется только в тех Modes, где его поток включён** (урок v7.5 и повторно v7.6): гейтированный поток при выключенном переключателе равен нулю, а его «пара» — нет.
- **Исполнитель-агент работает в нашем репозитории, контроль — на нашей стороне** (решение 2026-09-25): ветка `task/NNN-имя`, линейная история, scope задания читается из `main`; приватный репозиторий без защиты веток, поэтому каждая приёмка начинается с `tools/check_branch.mjs` (origin/main и теги на месте, scope, байты, SUMS), у которого есть свой самотест. Задания — `docs/tasks/`, правила — контракт §9.
- **Лицензия: своё — MIT, движок — AGPL** (решение 2026-09-25): модель, validation, policy, документация, стенд и tools свободны для использования, повторения и модификации (MIT, `LICENSE`); вендоренный `simulation` остаётся под AGPL-3.0-or-later, и распространение стенда вместе с ним подчиняется AGPL для движка. MIT совместима с AGPL-3.0. Подробно — `lab/LICENSE-NOTICE.md`.
- **Planet v1 — контракт из частей со счётчиками по процессам** (решение 2026-09-26, `docs/PLANET_V1_CONTRACT_RU.md`): счётчик граничных потоков дошёл до нуля и перестал вести. Planet v1 — без населения (оно в v2); недра — конечный сток из параметра, в v8 выводится из формирования планеты; исключения «константа / без энергии» допустимы с причиной и отдельным счётом, ужесточение — режим `planet_strict`.
- **Каноническая платформа для точных чисел — Windows x64 · Node 24.11.1** (решение 2026-09-25, вариант A по итогам задачи 006): `Math.pow` (оператор `^` модели) в Node округляет по-разному на Windows и Linux, поэтому ряды расходятся побитово во всех Modes; точные гейты приёмки и эталон `lab/reference/accepted/series-digest.windows.json` — только на канонической платформе, Linux CI — подсказка. Убрать зависимость — открытый пункт `ROADMAP.md`. Правило — `VERSIONING_AND_AUTHORITY.md` §8.
